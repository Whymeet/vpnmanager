# Установка appguard

> **Как начать.** Склонируй репозиторий и запусти в его папке `install.cmd` —
> один файл на все системы:
>
> ```bash
> git clone <адрес внутреннего репозитория vpnmanager>
> cd vpnmanager
> ./install.cmd        # macOS — в программе «Терминал»; Linux — в терминале
> .\install.cmd        # Windows — в PowerShell, или двойной щелчок в Проводнике
> ```
>
> Установка сама проверит систему, соберёт appguard и поставит службу, по шагам
> показывая, что делает; пароль администратора (на Windows — разрешение) спросит
> один раз. Потом — готовый конфиг и свои выходы VPN (шаг 5):
>
> ```bash
> appguard apply                # программы и сервисы из готового конфига
> appguard remember Германия    # свой выход VPN (VPN включён); повтори для каждого
> appguard rule mine            # сервисы открыты только через твои выходы
> ```
>
> Можно и через Claude Code: открой папку `appguard` и напиши «установи
> по `setup/README.md`» — он всё проверит и скажет, что запустить. Работает на
> macOS, Windows 10/11 и Linux с systemd.

appguard — фоновая служба: отмеченные приложения выходят в интернет только через
VPN, выход которого инструмент проверил сам. Без VPN, в момент переключения
между VPN и с российским выходом их сервисы закрыты.

## Если ты Claude и ведёшь установку

Человек, скорее всего, **без технического бэкграунда**. Держи это в голове на
каждом шаге.

1. **Команды с правами администратора выполняет только человек.** На macOS и
   Linux не запускай сам ни `sudo`, ни `install.cmd`, `setup/macos/install.sh` и
   `setup/linux/install.sh` (они спросят пароль), ни любую другую команду, которая
   спросит пароль от компьютера. На Windows не запускай `install.cmd`, `setup\windows\install.ps1`,
   `Start-Process -Verb RunAs` и ничего, что вызовет окно «Разрешить этому
   приложению вносить изменения?». Даже если человек просит сделать это за него.
   Скажи, какую программу открыть («Терминал» на macOS, PowerShell от имени
   администратора на Windows), что вставить (команду целиком, с путём к клону) и
   что на macOS пароль при вводе не виден. Дождись, пока человек напишет, чем
   кончилось.
2. **Один шаг — один результат.** Сделал шаг → коротко сказал, что получилось →
   перешёл к следующему. Не вываливай весь план сразу.
3. **Делай сам всё, что можешь сделать сам.** Клонирование, подготовка
   (`prepare.sh`: проверит систему, поставит Go и соберёт — без пароля, так
   проблемы видны до установки), проверка после установки — твоя работа.
4. **Никакого жаргона без расшифровки.** Не «задеплою демона в launchd», а
   «сейчас соберу программу, потом попрошу тебя один раз ввести пароль».
5. **Шаг не получился — остановись и скажи.** Не иди дальше, делая вид, что всё
   хорошо.
6. **Нет прав администратора — стоп.** Подготовка сама это проверит и
   остановится. Объясни, что под этой учётной записью установить нельзя, и не
   пытайся обойти: в системе к этому моменту ничего не изменено.
7. **Не удаляй инструмент без прямой просьбы человека.** `appguard uninstall`
   спрашивает подтверждение — отвечает на него человек, а не ты.
8. **Обновление — тоже команда с правами администратора.** Ты делаешь `git
   pull` в клоне, а `sudo appguard update` (macOS) или `appguard update` в
   PowerShell от имени администратора (Windows) выполняет человек — по
   разделу «Как обновиться».
9. **`appguard apply` — только при включённом VPN.** Готовый конфиг закрывает
   сервисы Anthropic вне проверенного VPN, и без VPN оборвётся и твоя сессия.
   Сначала `appguard status`: в строке VPN должно быть «проверен». На macOS и
   Linux `appguard apply` можешь запустить сам (пароль не нужен), на Windows её
   запускает человек в PowerShell от имени администратора. Выходы (`appguard
   remember`) и правило (`appguard rule mine`) — со слов человека: какие VPN его,
   знает только он.

## Главное, что нужно понять про этот инструмент

**Это системная служба, а не программа в окне.** Она работает с правами
администратора и стартует вместе с системой. На экране от неё только значок
рядом с часами: есть значок — служба отвечает, нет значка — не отвечает. Щит с
замком — защищённые приложения в сети, перечёркнутый щит — без сети. По щелчку —
небольшое меню: в сети ли приложения, адрес и страна выхода или причина, и
«Уведомления» — их можно выключить и включить (на macOS переключателем, на Windows
и Linux — отметкой). Остальное управление — командой `appguard` в терминале.

**Установка меняет систему.** Вот что именно — всё это снимает `appguard uninstall`.

На macOS:

| Что | Где |
|---|---|
| служба | `/Library/LaunchDaemons/com.appguard.daemon.plist` |
| сам инструмент и его настройки | `/Library/Application Support/appguard/` |
| команда `appguard` | `/usr/local/bin/appguard` |
| журнал службы | `/Library/Logs/appguard/` |
| правила встроенного файрвола | якорь pf `com.apple/100.appguard`; системный `/etc/pf.conf` не меняется |
| резолвер защищённых доменов | служба слушает `127.0.0.1:53535`; по файлу на домен в `/etc/resolver/` (чужие файлы там не трогаются) |
| значок в строке меню | `~/Library/LaunchAgents/com.appguard.tray.plist` того, кто ставил: при входе запускает `appguard tray`; вывод — `~/Library/Logs/appguard-tray.log`. Место значка macOS помнит в `com.apple.osascript`: эту строку настроек удаление оставляет, чтобы обновление не сбрасывало значок, перетащенный человеком; она ни на что не влияет |

На Windows:

| Что | Где |
|---|---|
| служба `appguard` | диспетчер служб Windows: автозапуск, от имени системы, перезапуск при сбое |
| сам инструмент | `C:\Program Files\appguard\` |
| команда `appguard` | папка `C:\Program Files\appguard\bin` дописана в системный `PATH` |
| настройки и журнал службы | `C:\ProgramData\appguard\` |
| резолвер защищённых доменов | служба слушает `127.53.53.53:53`; правила таблицы NRPT с пометкой `appguard` (чужие правила не трогаются) |
| фильтры защищённых приложений и адресов сервисов | Windows Filtering Platform: поставщик и подуровень `appguard`; правила Брандмауэра Защитника Windows не меняются |
| уведомления | задача планировщика `appguard-notify`: при входе в Windows запускает `appguardw.exe` (тот же appguard без окна консоли) |
| значок в области уведомлений | задача планировщика `appguard-tray`: при входе любого пользователя запускает `appguardw.exe tray` |
| ежедневное обновление каталога | задача планировщика `appguard-catalog` от твоего имени: раз в сутки и при входе — `git pull` в клоне |

На Linux:

| Что | Где |
|---|---|
| служба | `/etc/systemd/system/appguard.service`: стартует раньше сети |
| сам инструмент и его настройки | `/opt/appguard/` |
| команда `appguard` | `/usr/local/bin/appguard` |
| журнал службы | `/var/log/appguard/` |
| правила файрвола | своя таблица nftables `inet appguard`; чужие таблицы и `/etc/nftables.conf` не меняются |
| группа защищённых процессов | иерархия cgroup `net_cls` (смонтирована в `/run/appguard/net_cls`), в оперативной памяти |
| резолвер защищённых доменов | служба слушает `127.0.0.1:53535`; интерфейс-заглушка `appguard0` с доменами в systemd-resolved (нет systemd-resolved — ничего не меняется) |
| ежедневное обновление каталога | таймер `appguard-catalog.timer` от твоего имени: раз в сутки — `git pull` в клоне |
| значок в области значков | `/etc/xdg/autostart/appguard-tray.desktop`: при входе в рабочий стол запускает `appguard tray` у любого пользователя |
| расширение области значков (только на GNOME без неё) | системный пакет `gnome-shell-extension-appindicator`; удаление appguard его не снимает: им могут пользоваться другие программы |

> **Windows — в работе.** Сейчас на Windows ставится служба, работают статус,
> журнал и удаление; служба видит VPN и проверяет его выход. Приложения из
> меню «Пуск» и Store выходят в сеть только через проверенный VPN — и их
> обновления тоже; сайты их сервисов без VPN не открываются и в браузере;
> «Россия напрямую» замечается; об открытии и закрытии приходят уведомления;
> каталог обновляется сам; `appguard check` работает. Всё это пока не проверено
> на живой Windows.

**Настройки живут только на этом компьютере.** Они лежат в системной папке, а не
в клоне, и в репозиторий не попадают.

**Ключей, аккаунтов и переменных окружения нет** — заполнять ничего не нужно.

## Шаг 1. Что нужно

- macOS 12 или новее (Apple Silicon или Intel), Windows 10 или 11 (x64 или ARM64)
  либо Linux с systemd и ядром 5.15 или новее (x86_64 или aarch64: Ubuntu 22.04+,
  Debian 12+, Fedora и другие);
- учётная запись администратора (на Linux — в группе `sudo` или `wheel`) — её
  проверит подготовка;
- `git`, чтобы склонировать репозиторий;
- Go — подготовка поставит его сама, в папку клона и без прав администратора.

## Шаг 2. Клонирование

Репозиторий внутренний — адрес даёт тот, кто ведёт проект:

```bash
git clone <адрес внутреннего репозитория vpnmanager>
cd vpnmanager
```

Нет `git` — на macOS `xcode-select --install` (или `brew install git`), на
Windows `winget install --id Git.Git`, затем новое окно PowerShell. На Linux —
`sudo apt install git` (или пакет своего дистрибутива).

## Шаг 3. Установка — одна команда, запускает человек

### macOS

Открой программу **«Терминал»** (⌘ Пробел → «Терминал»), перейди в папку клона
и запусти установку:

```bash
cd /путь/к/клону/appguard
./install.cmd
```

`install.cmd` на маке просто передаёт работу `setup/macos/install.sh` — можно
запускать и его.

Установка идёт по шагам и пишет, что делает:

1. проверяет систему и права администратора — без них останавливается, ничего не
   изменив;
2. ищет Go, нужный для сборки; нет подходящего — скачивает его в `.toolchain/`
   клона (без пароля, удаляется вместе с клоном);
3. собирает appguard в `bin/appguard` — первый раз пару минут;
4. ставит службу — здесь Терминал спросит пароль от этого мака. Символы при вводе
   не видны — так и должно быть;
5. проверяет, что служба отвечает, и показывает её статус.

В конце — «✓ Готово» и что делать дальше. Повторный запуск обновляет установку,
настройки сохраняются. Шаги 1–3 Claude может пройти заранее, без пароля:
`./setup/macos/prepare.sh` — тогда установка повторит их за секунды.

Установка ставит и ежедневное обновление каталога приложений: раз в сутки оно
от твоего имени делает `git pull` в этом клоне и отдаёт каталог службе. Поэтому
клон не перемещай и не удаляй — переместил, поставь заново из нового места.

macOS может показать уведомление «Добавлены фоновые объекты» — это служба
appguard, обновление каталога и значок. Не выключай их в Системных настройках →
Основные → Объекты входа: иначе после перезагрузки служба не стартует, каталог
перестанет обновляться, а значка не будет.

Значок появляется в строке меню сразу после установки и потом при каждом входе в
систему, у той учётной записи, из которой запускали установку: монохромный щит,
правее других сторонних значков, у часов. Перетащить его можно с нажатой Cmd, место
сохранится. На экране входа значка нет: строки меню там ещё нет.

### Windows

Открой папку клона в Проводнике и дважды щёлкни `install.cmd`. Или в **обычном
окне PowerShell** (меню «Пуск» → набери «PowerShell» → Enter):

```powershell
cd C:\путь\к\клону\appguard
.\install.cmd
```

`install.cmd` запускает `setup\windows\install.ps1` с ключом, без которого
Windows не даёт запускать сценарии PowerShell; от имени администратора
открывать ничего не нужно. Шаги те же. На четвёртом Windows спросит «Разрешить этому приложению вносить
изменения?» — ответь «Да»: откроется окно установки и закроется само, а его
вывод появится в твоём окне. Команда `appguard` появится в новых окнах PowerShell
— в уже открытых её нет. Подготовка без прав администратора, которую может
запустить Claude, — `setup\windows\prepare.ps1`.

Значок appguard появляется в области уведомлений сразу после установки и потом при
входе любого пользователя. Windows прячет новые значки за стрелку `^` на панели
задач, а закрепить значок за человека программа не может. Сделай это один раз:
нажми `^` и перетащи значок appguard к часам. Либо Параметры → Персонализация → Панель
задач → «Другие значки на панели задач» → включи appguard.

### Linux

В терминале, от своей учётной записи, без `sudo`:

```bash
cd /путь/к/клону/appguard
./install.cmd
```

Шаги те же, что на macOS, и ещё один: система и права, Go, сборка, служба, значок,
проверка. На четвёртом `sudo` спросит пароль. Если в системе нет программы `nft`,
установка поставит пакет `nftables` сама. Перед изменениями установка проверяет, что
ядро умеет всё нужное; если нет — останавливается и пишет почему, ничего не изменив.
Шаги 1–3 Claude может пройти заранее, без пароля: `./setup/linux/prepare.sh`.

Шаг «значок» запускает значок сразу, если есть графический сеанс, и ставит то, чего
ему не хватает. На Ubuntu и KDE ставить нечего. На чистом GNOME (Fedora, Debian) нет
области значков: установка ставит пакет `gnome-shell-extension-appindicator` и
включает расширение, значок появится после следующего входа в систему. Без области
значков (оконный менеджер без панели) значка не будет; установка скажет об этом.
Отсутствие значка там не значит, что служба упала. На сервере без рабочего стола шаг
ничего не делает. Этот шаг никогда не прерывает установку: защита от значка не
зависит.

Клон не перемещай и не удаляй: из него раз в сутки обновляется каталог.

## Шаг 4. Проверить

```bash
appguard status
```

Должно быть `Служба: работает с <дата и время>, версия <номер>`, а ниже — строка
про VPN: при включённом VPN — его туннель, адрес и страна выхода и «проверен»,
без VPN — `VPN: нет`. Статус доступен любому пользователю этого компьютера, без
пароля. На Windows — из обычного окна PowerShell; менять настройки там можно
только из PowerShell от имени администратора.

Рядом с часами должен быть значок appguard: на macOS — в строке меню, на Windows — в
области уведомлений (возможно, за стрелкой `^`), на Linux — в области значков. При
включённом VPN это щит с замком, без VPN — перечёркнутый щит. Щелчок открывает
меню: «Приложения в сети» и адрес выхода (или «Приложения без сети» и причина) и
«Уведомления».

Уведомления приходят, когда защищённые приложения выходят в сеть (с адресом и
страной выхода) и когда остаются без сети дольше 15 секунд: переподключение VPN
уведомлений не даёт. Если они мешают, выключи «Уведомления» в меню значка или
выполни `appguard notifications off` — состояние видно по картинке значка, а
журнал пишется всё равно. Прав администратора для этого не нужно.

Что делает служба и почему, видно в журнале — события за неделю и новые по мере
появления (выход — Ctrl+C):

```bash
appguard log
```

Если в клиенте VPN включено правило «Россия напрямую» (российские адреса — мимо
туннеля; так по умолчанию делают Hiddify и некоторые профили Happ), `appguard status` и
`appguard log` скажут об этом и подскажут выключить его в клиенте: у зарубежных сервисов
бывают узлы в России, и запрос к ним уходит с домашнего адреса. appguard такие
прямые соединения к защищённым сервисам закрывает, но правило лучше выключить.

## Шаг 5. Готовый конфиг и свои выходы

Три команды. На macOS и Linux — в терминале, без `sudo`; на Windows — в
PowerShell от имени администратора. VPN при этом включён:

```bash
appguard apply                    # программы и сервисы из готового конфига
appguard remember Германия        # свой выход VPN; повтори для каждого своего VPN
appguard rule mine                # сервисы открыты только через твои выходы
```

**Готовый конфиг** лежит в клоне, по файлу на систему: `configs/macos.conf`,
`configs/linux.conf`, `configs/windows.conf`. `appguard apply` сама берёт файл
своей системы: какая это система, программа знает с момента сборки. Команду можно
запускать из любой папки — клон она найдёт сама. Сначала она проверяет файл
целиком: ошибка в любой строке — ничего не изменено. Потом применяет его по
строке и показывает каждую, в конце — статус и «✓ Готово». Программу, которой на
компьютере нет, пропускает; поставишь её — запусти `appguard apply` ещё раз, уже
настроенное останется как есть. Конфиг только добавляет: снять защиту —
`appguard remove`, `appguard unprotect`. Свой файл — `appguard apply ~/my.conf`,
формат описан в начале каждого конфига.

Конфиг закрывает сервисы Anthropic вне проверенного VPN: без VPN Claude и
Claude Code перестанут отвечать. Так и задумано, поэтому применяй его с
включённым VPN.

**Правило** одно на все приложения. По умолчанию — «любой выход не из России»:
сервисы открыты, пока выход VPN проверен и он не в России. Чтобы сервисы видели
только твои адреса, подключи свой VPN и запомни его выход — `appguard remember
<имя>` (или пункт меню «Запомнить текущий выход»), — повтори для каждого своего
VPN, а потом включи правило «только мои выходы»: `appguard rule mine`. Порядок
важен: при правиле «только мои выходы» и пустом списке сервисы закрыты. Адрес
вводить не нужно: запоминается адрес выхода, который служба проверила сама.
Российский выход не запоминается.

Выход можно запомнить и заранее, не переключаясь на этот VPN, — по адресу:
`appguard remember Сингапур 203.0.113.5`. Нужен адрес выхода — тот, что видят
сайты, — а не адрес сервера из настроек VPN: у цепочек и серверов за CDN они
разные. Пока служба не вышла через него сама, в списке он «введён вручную, ещё
не проверен». Ошибка в адресе ничего не открывает: сервисы через такой выход
откроются, только если служба его проверила, а российский — никогда. Убрать
выход из списка — `appguard forget Сингапур` (или его адрес) либо пункт меню
«Забыть выход».

### Защитить что-то своё

То, чего нет в готовом конфиге, добавляется по одному — через меню:

```bash
appguard
```

Пункты выбираются стрелками, Enter — открыть. В «Добавить приложение» — список
установленных приложений; буквы сужают список, Enter добавляет выбранное.
Приложение из каталога (`catalog/catalog.json`) **защищено сразу**.
Остальные на macOS сначала **ждут обучения**: включи VPN и поработай в
приложении пару минут — служба запомнит, куда оно ходит, и статус сменится на
«защищено». С этого момента без проверенного VPN оно не получает сеть, а сайт
этого сервиса не открывается и в браузере. Программы из готового конфига (Claude
Code — `claude`) учатся так же.

Каждый пункт меню есть и командой: `appguard add Notion`, `appguard remove
Notion`, `appguard remember Server 1`, `appguard rule mine`, `appguard status` —
полный список в `appguard help`. Снять защиту можно
только целиком — паузы нет, и перед снятием appguard предупредит, что приложение
начнёт выходить в сеть с домашнего адреса.

**Перенести защиту на другой компьютер** можно одним файлом. Там, где приложения
уже обучены, — `appguard catalog export ~/appguard-export.json`; на новом —
`appguard import ~/appguard-export.json`: все домены и адреса из файла закрыты
сразу, без обучения. Подойдёт и простой список — по домену, адресу или ссылке
на строку, `#` — комментарий. Отдельный домен или адрес — `appguard protect
claude.ai 160.79.104.10`, снять — `appguard unprotect`. Что защищено вручную,
видно в `appguard status`.

**Консольные программы на macOS** (Claude Code, Codex) защищаются так же — по
имени команды: `appguard add claude` или по пути: `appguard add
~/.local/bin/claude`. Имя с большой буквы — приложение (`appguard add Claude` —
это Claude.app), с маленькой — команда. Программа ждёт обучения: включи VPN и
поработай в ней пару минут. Учится она только в эти минуты, поэтому не проси её
тогда открывать сайты: всё, куда она сходит, станет её адресами и без VPN
закроется для всех программ. Потом к ней добавляются только новые имена её же
доменов.

**Что выучило приложение** — `appguard status claude` (или `appguard status
Notion`): его адреса и домены. Выученное по ошибке — например, сайт, который
Claude Code открыл во время обучения, — убирает `appguard forget claude
example.com 203.0.113.50`: без VPN это больше не закрыто, и само приложение его
больше не выучит. Убирай только чужое: свой адрес сервиса приложение тогда
сможет открыть и без VPN.

**На Windows** меню и команды запускают в PowerShell от имени администратора.
В «Добавить приложение» — программы из меню «Пуск» и приложения Store. Любое
выбранное **защищено сразу**, без обучения: под защиту встаёт вся папка его
установки — вспомогательные программы, обновлятор и будущие версии тоже. Можно и
по пути к программе: `appguard add "C:\Program Files\Notion\Notion.exe"`.
Если клиент VPN работает в режиме системного прокси, защищённым приложениям
порт прокси открыт, только пока выход через него проверен; остальные программы
прокси не теряют.

**На Linux** программа защищается одной командой, по имени, и **сразу, без
обучения**:

```bash
appguard add firefox             # программа или служба по имени, пакет snap тоже
appguard add nginx.service       # только служба systemd
appguard add /opt/myapp/run      # по пути
appguard add                     # выбрать из списка: меню приложений и службы
appguard status                  # что защищено и какой выход сейчас
appguard remove firefox          # снять защиту
```

С этого момента у программы нет сети без проверенного VPN: и новых запусков, и
уже работающих процессов — их открытые соединения обрываются. Запускать её
заново и настраивать `sudo` не нужно. Защищается вся папка установки программы
вместе с вспомогательными файлами, а в общих папках вроде `/usr/bin` — только сам
файл. У пакета snap защищается весь пакет, обновления snap остаются под защитой.
Дочерние процессы закрыты вместе с родителем. Служба закрывается без перезапуска и
без правки её юнита. Если у службы и команды одно имя и это одна программа
(`appguard add nginx`), закрыта и служба, и запуск той же программы руками.

Выпускать только через **свои адреса выхода** — те же две команды, что и на других
системах:

```bash
appguard remember Сервер 203.0.113.5     # адрес выхода, который видят сайты
appguard rule mine                       # только через мои выходы
```

Закрытой программе остаются петля (локальные службы на этом компьютере) и DNS
роутера в локальной сети; весь её остальной трафик идёт только через проверенный
туннель, а куда — не ограничивается.

Что на Linux работает иначе:

- **Режим системного прокси** клиента VPN не поддерживается: нужен режим TUN
  (интерфейс туннеля). В прокси-режиме appguard VPN не увидит, и приложения останутся
  закрытыми.
- **Контейнеры Docker не закрываются:** внутри контейнера другие файлы. Сам
  `dockerd` защитить можно, контейнеры — нет.
- **Скрипт через интерпретатор** (`python3 bot.py`, в том числе из его папки)
  защищается путём к скрипту и попадает под защиту в течение двух секунд после
  запуска: перехватить можно только запуск файла. Новая папка внутри защищённой
  программы — до 10 секунд.
- **Сам интерпретатор защитить нельзя:** `appguard add python3` откажет, иначе
  закрылось бы всё, что на нём работает. То же с `sh`, `bash`, `node`, `java`.
  Защищай скрипт или программу: `appguard add /opt/bot/bot.py`.
- **Flatpak не поддерживается:** ярлыки Flatpak в списке не показываются, потому что
  процесс приложения снаружи песочницы не отличить. Ставь программу как пакет
  системы или snap.
- **Программа переехала.** Если обновление перенесло её в новую папку (ссылка
  `/usr/local/bin/foo` смотрит уже на другую версию), новая версия не защищена,
  пока её не добавят заново. `appguard check` покажет это отдельным пунктом.
- **Пока служба не работает**, новый запуск защищённой программы не перехватывается:
  падение закрывается за пару секунд, а после `systemctl stop appguard` — только
  когда службу запустят снова. Уже запущенные программы и адреса сервисов всё это
  время закрыты, а при старте служба закрывает всё, что успело запуститься.
- **VPN нужен с интерфейсом туннеля.** Проверено на WireGuard в ядре. Клиенты с TUN
  устроены проще и должны работать так же, но живьём не проверялись. IPsec без
  отдельного интерфейса служба как туннель не видит.
- **Домены сайтов** закрываются только с systemd-resolved. Без него `appguard protect
  <домен>` не сработает, адреса (`appguard protect 203.0.113.5`) — закрываются.
- **Ядро без `net_cls`** (свежие сборки openSUSE Tumbleweed) не подходит: установка
  остановится и скажет об этом.

## Если что-то пошло не так

- **«нет прав администратора»** — под этой учётной записью установить нельзя, в
  системе ничего не изменено. Нужна учётная запись администратора: Системные
  настройки → Пользователи и группы.
- **«Не удалось скачать Go»** — не открылись ни go.dev, ни зеркало
  mirrors.aliyun.com; под сообщением — причина по каждому адресу. Включи VPN в
  режиме полного туннеля (в v2rayN — TUN, не «системный прокси») и запусти
  установку ещё раз.
- **`appguard: command not found` после установки** — открой новое окно
  терминала. Не помогло — команда лежит в `/usr/local/bin`: проверь, что эта папка
  есть в `PATH` (`echo $PATH`).
- **«Служба: не отвечает»** — обычно она перезапускается сама за несколько
  секунд. Если сообщение держится, причина — в `/Library/Logs/appguard/daemon.log`
  (на Windows — `C:\ProgramData\appguard\logs\daemon.log`).
- **Нет значка, а `appguard status` показывает, что служба работает** — значок живёт
  отдельно от службы, и защита от него не зависит. На macOS проверь Системные
  настройки → Основные → Объекты входа и настройку «Разрешить в строке меню», а
  вывод значка — в `~/Library/Logs/appguard-tray.log`. На маке с вырезом значок может
  не поместиться в строку меню. На Windows посмотри за стрелкой `^`. На Linux —
  установка говорила, что будет после следующего входа; на GNOME проверь расширение
  (`gnome-extensions list --enabled`).
- **Windows: «appguard не распознано как имя командлета»** — открой новое окно
  PowerShell: в окнах, открытых до установки, команды нет.
- **Windows: «Менять настройки appguard можно только из PowerShell, открытого от
  имени администратора»** — так и есть: `status` и `log` работают в обычном окне,
  а добавить приложение, сменить правило или удалить — в окне PowerShell от
  имени администратора.
- **Windows: «выполнение сценариев отключено в этой системе»** — скрипт
  запустили без `powershell -NoProfile -ExecutionPolicy Bypass -File`. Вставь
  команду целиком, как в шаге 3, или запусти `install.cmd`.
- **Windows: «Windows не дал прав администратора»** — на вопрос «Разрешить этому
  приложению вносить изменения?» ответили «Нет». Ничего не изменено: запусти
  установку ещё раз и ответь «Да».
- **Windows: «Не нашёл клон appguard» у `appguard update` или `appguard apply`** —
  версия 0.21.0 не узнавала клон, который Git для Windows скачал с переводами
  строк Windows. Запусти в папке клона `install.cmd` ещё раз (двойной щелчок или
  `.\install.cmd`): установка обновится, настройки сохранятся, а `update` и
  `apply` дальше найдут клон сами.
- **Linux: «Нет systemd»** — appguard работает службой systemd: в контейнере и на
  системах без него установка невозможна.
- **Linux: «в ядре нет контроллера net_cls»** — ядро собрано без него (свежие
  openSUSE Tumbleweed). Нужно другое ядро или другой дистрибутив; ничего не изменено.
- **Linux: «Служба: не отвечает»** — причина в `/var/log/appguard/daemon.log` и в
  `systemctl status appguard`.
- **«/usr/local/bin/appguard уже есть, и это не команда appguard»** — там лежит
  чужой файл с тем же именем, и установка его не трогает. Человек убирает его
  сам (`sudo rm /usr/local/bin/appguard`) и запускает установку ещё раз.

## Удаление

```bash
appguard uninstall
```

Команда предупреждает, что защищённые приложения начнут выходить в сеть с
домашнего адреса, и удаляет только после ответа «да». Пароль не нужен: удалить
может любой администратор этого компьютера. Снимаются служба, ежедневное обновление
каталога, значок и его автозапуск, правила файрвола, доменные резолверы, её настройки
и все файлы установки. Папка клона остаётся — это обычная папка.

Если служба не отвечает, удаление идёт с паролем — его выполняет человек:
`sudo appguard uninstall`.

На Windows удаление запускают в PowerShell от имени администратора — его
выполняет человек: `appguard uninstall`. Снимаются служба, задачи уведомлений,
значка и обновления каталога, фильтры WFP, правила NRPT, папка команды в `PATH`,
настройки и файлы установки. Значок исчезает сам в течение нескольких секунд.
Работающий `appguard.exe` Windows удалить не даёт — он уезжает во временную папку
Windows и исчезает при следующей загрузке.

## Как обновиться

Каталог приложений обновляется сам, раз в сутки: `git pull` в клоне только
перематывает вперёд — без слияний, локальные правки не трогаются. Если не вышло
(доступ к репозиторию закрыт, история разошлась, клона нет на месте), защита
работает на последнем каталоге, а `appguard status` и `appguard log` объясняют
почему. Каталог старше недели или новая версия в клоне — они же напоминают
обновиться. Вручную: `git pull`, затем `appguard catalog load`.

Новые версии выходят коммитами в этот репозиторий. Обновление — два шага:

1. **`git pull` в клоне** — делает Claude (пароль не нужен).
2. **«Обновить»** — делает человек, как установку: это команда с правами
   администратора. Она пересобирает appguard из клона и ставит новую версию
   поверх прежней; служба перезапускается с теми же настройками.

   На macOS и Linux — в терминале, с паролем:

   ```bash
   sudo appguard update
   ```

   На Windows — в PowerShell от имени администратора:

   ```powershell
   appguard update
   ```

   Команду можно запускать из любой папки: она обновляет из клона, из которого
   appguard ставили (или из текущей папки, если это клон; или из указанной:
   `appguard update <папка клона>`). Пункт «Обновить» есть и в меню.

Пока служба перезапускается, защита не прерывается: на macOS и Linux правила
файрвола остаются в системе, на Windows действуют постоянные фильтры, и защищённое
закрыто, пока новая служба не проверит выход. Не вышло — работает прежняя
версия, настройки на месте, а команда пишет почему.

Если `git pull` отказывается («divergent branches», «refusing to merge») —
история репозитория переписана. Склонируй его заново в новую папку (шаг 2) и
повтори шаг 3 уже из неё: настройки живут в системе, а не в клоне, и
сохранятся. Старую папку клона после этого можно удалить.

### Был vpnlock — переход на appguard

С версии 0.23.0 инструмент называется **appguard**, а репозиторий переехал в
https://github.com/XoDefender/appguard (старый адрес перенаправляет туда же).
`vpnlock update` новую версию не поставит и напишет «Не нашёл клон vpnlock».
Переход — один раз, как установка:

1. **`git pull` в клоне** — делает Claude. Ежедневное обновление каталога
   могло уже сделать его само.
2. **`./install.cmd` в папке клона** — делает человек (шаг 3): на macOS и Linux
   в терминале, на Windows — в PowerShell или двойным щелчком.

Установка сама найдёт vpnlock, перенесёт его настройки — защищённые
приложения, запомненные выходы, правило, уведомления — и снимет его его же
командой: службу, значок, правила файрвола и резолверы. В конце она скажет
«Прежний vpnlock снят, его настройки перенесены». Дальше команда — `appguard`
вместо `vpnlock`: `appguard status` покажет то же, что раньше `vpnlock status`.
Если vpnlock снять не вышло, appguard не ставится, а vpnlock продолжает работать.
